## Risks & open questions

- **R1 — TypeScript version.** Latest is 7.0, but typescript-eslint supports `<6.1`.
  Recommendation: pin `typescript ~6.0` — type-aware lint (`no-floating-promises`) needs it;
  move to 7 as its own spec when typescript-eslint supports it.
- **R2 — React lint plugin.** `eslint-plugin-react` was last released April 2025 (>12 months,
  fails `docs/security.md` Dependencies) and does not support ESLint 10. Recommendation: no React
  plugin; ban `dangerouslySetInnerHTML` with core `no-restricted-syntax` — zero dependencies,
  same protection (AC-6 proves it).
- **R3 — Running TS in Node.** The API runs with Node 24's built-in type stripping
  (`node src/server.ts`), no `tsx`/build step. It may print an experimental warning.
  Recommendation: accept; `erasableSyntaxOnly` already guarantees strippable code.
- **R4 — Contracts import.** `apps/api` imports `@leave/contracts` with `import type` only, so
  Node never loads the `.ts` file at runtime (type stripping refuses files under
  `node_modules`). Recommendation: keep contracts type-only until a spec needs runtime values.
- **R5 — `npm ci` in full check.** It deletes and reinstalls `node_modules` each full run
  (~tens of seconds). Recommendation: accept — it is full-only and proves AC-1 every run.
- **Dependencies to approve** (all MIT, TypeScript Apache-2.0, all released within 12 months):
  runtime `fastify` 5, `react` + `react-dom` 19; dev `typescript` 6.0, `@types/node` 24,
  `@types/react`, `@types/react-dom`, `vite` 8, `@vitejs/plugin-react` 6, `vitest` 5,
  `eslint` 10, `@eslint/js` 10, `typescript-eslint` 8, `prettier` 3.
- **Environment:** doctor has no profile verdict yet (no steps). The planned prerequisites are
  met on this machine: Node v24.18.0 (`requires test`), `npm ping` PONG (`requires audit`).
  Expected verdict after step 5: fast + full runnable here; CI gets Node 24 via `setup-node`.
